include::partial$trilha.adoc[]

[NOTE.antes]
====
**Antes:** nada -- esta parte só lê status de policy. O texto se refere aos
tiers da parte {p-planos}, mas nenhum comando aqui depende dele.
====

O par aqui é Gateway contra rota. As policies que miram o `prod-web` valem
para toda rota anexada, e **cedem** onde a rota declara a sua.

Nada aqui muda o ambiente: são três leituras, uma por passo.

== Passo 1 -- pergunte ao teto se ele está valendo

A `prod-web-deny-all` é a policy que nega tudo, presa ao Gateway. O comando lê
só as condições do status dela.

[source,bash,role="execute"]
----
oc get authpolicy prod-web-deny-all -n ingress-gateway -o jsonpath='{range .status.conditions[*]}{.type}={.status} ({.message}){"\n"}{end}'
----

[source,text]
----
Accepted=True (AuthPolicy has been accepted)
Enforced=False (AuthPolicy is overridden by [travel-agency/travel-agency-authpolicy ingress-gateway/pega-tudo-421])
----

.O que este comando faz?
[%collapsible]
====
`-o jsonpath` escolhe o que mostrar do objeto. Aqui ele percorre a lista
`status.conditions` e imprime, de cada condição, o tipo, o valor e a mensagem.
É o mesmo que `oc get ... -o yaml` mostra no fim do arquivo, sem o resto.
====

**O que isso diz:** `Accepted=True` -- a policy foi entendida. `Enforced=False`
-- ela **não** está valendo, e a mensagem **nomeia** quem a sobrepôs: a policy
da rota da API de viagens. O teto não foi apagado nem falhou; ele cedeu, e
disse para quem.

A lista entre colchetes traz **todas** as rotas que sobrepuseram o teto. A
segunda é da própria plataforma: `pega-tudo-421` é a policy de uma rota sem
hostname, no projeto do Gateway, que responde `421` a todo nome que o Gateway
não atende -- é o que faz o navegador, quando reaproveita a conexão da API para
abrir o portal ou o Grafana, tentar de novo pelo caminho certo em vez de levar
um `404`. Se você voltar aqui depois de publicar a sua própria API, na parte
xref:m1-06-exposta.adoc[{p-exposta}], ela aparece na lista também.

== Passo 2 -- a mesma pergunta, para o limite

O Gateway também carrega um limite padrão, a `ingress-gateway-rlp-lowlimits`.

[source,bash,role="execute"]
----
oc get ratelimitpolicy ingress-gateway-rlp-lowlimits -n ingress-gateway -o jsonpath='{range .status.conditions[*]}{.type}={.status} ({.message}){"\n"}{end}'
----

[source,text]
----
Accepted=True (RateLimitPolicy has been accepted)
Enforced=True (RateLimitPolicy has been partially enforced)
----

**O que isso diz:** `partially` -- o limite do Gateway vale em parte das rotas.
Na rota da API de viagens ele cedeu aos planos comerciais dela (a
`travels-plans`, a `PlanPolicy` da parte {p-planos}, que gera uma
`RateLimitPolicy` de mesmo nome). Na `pega-tudo` ele vale, porque aquela rota
não declara limite próprio. A regra é a mesma para acesso e para limite: o mais
específico prevalece, e o status diz onde. Numa pilha de anotações de ingress,
responder "qual regra valeu para esta rota?" é arqueologia; aqui é um campo.

== Passo 3 -- veja no que a policy virou, dentro do Gateway

Ninguém escreveu à mão o que o Gateway executa. O comando abre a configuração
que o Connectivity Link gerou para ele e filtra as linhas que falam de plano.

[source,bash,role="execute"]
----
oc get envoyfilter kuadrant-prod-web -n ingress-gateway -o jsonpath='{.spec.configPatches[0].patch.value.typed_config.value.config.configuration.value}' | python3 -m json.tool | grep -E 'auth.kuadrant.plan|metrics.labels'
----

[source,text]
----
                                "auth.kuadrant.plan == \"free\""
                                "auth.kuadrant.plan == \"gold\""
                                "auth.kuadrant.plan == \"silver\""
                                "auth.kuadrant.plan == \"unclassified\""
        "metrics.labels.method": "request.method",
        "metrics.labels.plan": "auth.kuadrant.plan",
        "metrics.labels.vhost": "request.host"
----

**O que isso diz:** uma policy declarativa de trinta linhas virou regra dentro
do proxy: um predicado por plano, e o plano como rótulo de métrica. É o que a
parte xref:m1-02-planos.adoc[{p-planos}] mede pelo lado de fora, e a
xref:m1-05-negocio.adoc[{p-negocio}] transforma em painel.

O status, a console também mostra -- em duas telas:

* {openshift_console_url}/kuadrant/policies/ns/ingress-gateway[Connectivity Link → Policies, no projeto do Gateway^]:
  o `prod-web-deny-all` aparece como **Overridden (Not Enforced)** -- a policy
  da rota venceu na rota dela -- e o limite do Gateway, como **Enforced**,
  porque vale em parte das rotas (o `partially` do Passo 2). É a precedência
  desta parte numa linha de tabela.
* o Gateway {openshift_console_url}/k8s/ns/ingress-gateway/gateway.networking.k8s.io{tilde}v1{tilde}Gateway/prod-web[`prod-web`^],
  em *Conditions*: `AuthPolicyAffected` e `RateLimitPolicyAffected`, cada uma
  com o nome da policy. O Gateway diz quem o afeta.

ifdef::perfis[]
[IMPORTANT]
.Esta tela é do cluster, não sua
====
A Policy Topology desenha o que o operator do Connectivity Link gerencia -- e
há **um operator por cluster**. Por isso você vê os Gateways e as rotas dos
colegas, e também objetos que ninguém criou à mão, como os `AuthConfig` que o
operator gera a partir de cada `AuthPolicy`. É a tela de quem **opera a
plataforma**. O endereço com o seu projeto não filtra o desenho: o objeto que
ela lê é um só, e o acesso a ele é tudo ou nada.
ifeval::["{usuario_console_plataforma}" != ""]
Por isso ela não abre com nenhum dos seus dois perfis, e sim com o login de
quem opera a plataforma: dar o mapa ao seu perfil Infra misturaria "os meus
projetos" com "o cluster de todos".
endif::[]
ifeval::["{usuario_console_plataforma}" == ""]
Por isso o perfil Dev nem a abre.
endif::[]

Duas perguntas para fazer ao desenho:

* **Qual é a sua parte?** O Gateway `prod-web` e a rota da API do seu ambiente
  -- os nomes terminam com o seu usuário. É o nome e o namespace que dizem de
  quem é cada objeto, não o lugar no desenho.
* **O que é o `AuthConfig` que você não criou?** É o que o operator derivou da
  sua `AuthPolicy`, e o que o Authorino executa. Você declarou a intenção; a
  plataforma gerou o resto.
====

A sua parte do mesmo desenho, recortada no terminal:

[source,bash,role="execute"]
----
bash scripts/topologia.sh
----

[source,text]
----
  Gateway prod-web  (ingress-gateway-...)
    <- AuthPolicy prod-web-deny-all
    <- RateLimitPolicy ingress-gateway-rlp-lowlimits
    Listener api
      HTTPRoute travel-agency-...  (travel-agency-...)
        <- AuthPolicy travel-agency-authpolicy
        <- RateLimitPolicy travels-plans
        regra rule-1 -> AuthConfig 8e96622fa0d0... (gerado)
    gerado pelo operator no Gateway:
      EnvoyFilter kuadrant-auth-prod-web
      ...
----

É a bifurcação desta parte, em texto: as duas policies do Gateway em cima, as
da rota embaixo. O script lê o **mesmo** objeto que a console desenha e
mostra só os seus namespaces.
endif::[]

== Evidência

[source,bash,role="execute"]
----
oc get limitador limitador -n kuadrant-system -o jsonpath='{.spec.limits}' | python3 -c 'import json,sys; [print(x["name"], x["max_value"], "a cada", x["seconds"], "s") for x in sorted(json.load(sys.stdin), key=lambda x: (x["name"], -x["seconds"])) if x["namespace"].startswith("travel-agency/")]'
----

[source,text]
----
free 1000 a cada 86400 s
free 3 a cada 10 s
gold 100000 a cada 86400 s
gold 30 a cada 10 s
silver 10000 a cada 86400 s
silver 10 a cada 10 s
unclassified 1 a cada 60 s
----

Um contador por tier, gerado pela policy. É a prova material de que a
declaração virou configuração de data plane sem ninguém escrever. O filtro
mostra só os da sua API: o Limitador é um só para o cluster, e guarda os
contadores de todas as rotas que têm limite.

== Configuração

A precedência não está em arquivo nenhum: está no **status**, que o Passo 1
leu. Os dois lados do par estão, e a diferença entre eles é uma linha, o
`targetRef` -- a `prod-web-deny-all` (o teto) mira o **Gateway**, a
`travel-agency-authpolicy` (a exceção) mira a **rota**:

[source,bash,role="execute"]
----
oc get authpolicy prod-web-deny-all -n ingress-gateway -o jsonpath='{.spec.targetRef}{"\n"}'
oc get authpolicy travel-agency-authpolicy -n travel-agency -o jsonpath='{.spec.targetRef}{"\n"}'
----

== O que isso prova

O cluster **declara** quem prevaleceu, num campo de status que você acabou de
ler. Numa pilha de anotações de ingress ou de `EnvoyFilter` solto, responder
"qual regra valeu para esta rota?" é arqueologia -- e costuma terminar em
tentativa e erro no ambiente de produção.
