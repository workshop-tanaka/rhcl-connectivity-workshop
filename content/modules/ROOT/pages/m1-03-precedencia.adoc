= {p-precedencia} Precedência de policies é explícita
:navtitle: {p-precedencia} Precedência de policies

**Para quem:** Engenheiro de Plataforma -- quem responde "qual policy venceu?" sem arqueologia. · **4 min**

[NOTE.antes]
====
**Antes:** nada -- esta parte só lê status de policy. O texto se refere aos
tiers da parte {p-planos}, mas nenhum comando aqui depende dele.
====

O par aqui é Gateway contra rota. As policies que miram o `prod-web` valem
para toda rota anexada, e **cedem** onde a rota declara a sua.

== Terminal

[source,bash,role="execute"]
----
bash scripts/demo.sh ato3
----

O que tem de aparecer: `Enforced=False`, e a mensagem **nomeia** quem venceu
-- as policies das duas rotas. Depois, os artefatos que o PlanPolicy gerou
sozinho: um contador por tier no Limitador e os predicados no filtro do Envoy.

== Navegador

{openshift_console_url}/kuadrant/policy-topology[Policy Topology^] -- o listener bifurca para
as rotas e as policies chegam tracejadas. **Não procure o vencedor aqui**: o
grafo faz a pergunta, o status do terminal responde.

== Evidência

[source,bash,role="execute"]
----
oc get limitador limitador -n kuadrant-system -o jsonpath='{.spec.limits}' | python3 -m json.tool | head -30
----

Um contador por tier, gerado pela policy. É a prova material de que a
declaração virou configuração de data plane sem ninguém escrever.

== Configuração

A precedência não está num arquivo: está no **status**. Mas os dois lados do
par estão, e vale vê-los lado a lado no editor:

Compare os dois lados do par: a `prod-web-deny-all` (o teto, que mira o
**Gateway**) e a `travel-agency-authpolicy` (a exceção, que mira a **rota**).
A diferença entre os dois é uma linha, o `targetRef`:

[source,bash,role="execute"]
----
oc get authpolicy prod-web-deny-all -n ingress-gateway -o jsonpath='{.spec.targetRef}{"\n"}'
oc get authpolicy travel-agency-authpolicy -n travel-agency -o jsonpath='{.spec.targetRef}{"\n"}'
----


{ide_url}[Abrir o repositório de policies no Dev Spaces^] se preferir os dois
lado a lado num editor.

E a precedência não está em nenhum dos dois arquivos:

[source,bash,role="execute"]
----
oc get authpolicy prod-web-deny-all -n ingress-gateway -o jsonpath='{range .status.conditions[*]}{.type}={.status} ({.message}){"\n"}{end}'
----

== O que isso prova

O cluster **declara** quem prevaleceu, num campo de status que você acabou de
ler. Numa pilha de anotações de ingress ou de `EnvoyFilter` solto, responder
"qual regra valeu para esta rota?" é arqueologia -- e costuma terminar em
tentativa e erro no ambiente de produção.
