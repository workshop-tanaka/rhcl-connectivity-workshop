= Se algo não responder
:navtitle: Se algo não responder

O ambiente é criado do zero para você, e uma peça ou outra pode demorar mais
que as demais. Esta página junta o que fazer quando uma parte devolve um painel
vazio, uma tela que não abre ou um comando que não acha o arquivo. Volte a ela
no meio do caminho; não é preciso lê-la antes de começar.

Antes de consertar qualquer coisa, peça o veredito em
xref:ambiente-conferir.adoc[Conferir o ambiente]: ele diz se o problema é do
ambiente ou da parte. Para desfazer uma parte e começar de novo, veja
xref:ambiente-recomecar.adoc[Recomeçar uma parte].

== `No such file or directory`

Se um comando responder `bash: scripts/demo.sh: No such file or directory`, o
terminal saiu do diretório do workshop. Volte com:

[source,bash,role="execute"]
----
cd /home/lab-user/rhcl-connectivity-demo
----

O caminho é absoluto de propósito: neste terminal `~` aponta para `/data`, que
não é gravável; `/home/lab-user` é o volume persistente.

== Um painel do Grafana vazio

Os painéis de consumo contam o tráfego dos **últimos 15 minutos**. Se você
chegou à parte {p-negocio} sem ter rodado a {p-planos} pouco antes, ou voltou
de uma pausa longa, a linha sai achatada. O aquecimento gera esse tráfego:

[source,bash,role="execute"]
----
bash scripts/demo.sh aquece --auto
----

São três minutos de tráfego de fundo e **depois** o reset das cotas. A ordem
é obrigatória: o aquecimento queima cota diária, e o reset a devolve. Rode-o
logo antes da parte que mostra o painel, e não no começo do workshop.

== O merge request saiu como *Draft*

O GitLab abre como rascunho (*Draft:* no título) o merge request cujo branch
não traz **nenhum commit** além do `main` -- medido neste ambiente: os quatro
merge requests vazios de uma rodada saíram *Draft*, e nenhum dos que tinham
commit. Acontece quando o commit da mudança não foi para o branch. Na parte
xref:esteira-mr.adoc[{p-mr}Mudança por merge request], confira:

[source,bash,role="execute perfil-dev"]
----
git log --oneline origin/main..plano-free-6
----

Sem nenhuma linha, rode de novo o passo 2 daquela parte e depois o push: o `-f`
substitui o branch antigo, e o mesmo merge request passa a mostrar a mudança.

== Como o `demo.sh` funciona

As partes do guia mandam rodar cada comando à mão. O `demo.sh` é o que está
por trás do veredito, do aquecimento e da lista de telas desta área, e também
percorre a demonstração inteira de uma vez.

.Os passos, as pausas e os desvios
[%collapsible]
====
Cada passo **pausa antes de executar**: `Enter` segue, `p` pula, `Ctrl-C` sai.
Ele mostra o comando na tela antes de rodar, roda, e diz o que olhar na saída.

[cols="1,3"]
|===
| `◇ depende:` | a linha abaixo do título diz o que o passo pressupõe. Quando falta, o script **pergunta** se roda o anterior agora e volta.
| Desvio | na pausa, digite o nome de outro passo do roteiro (`ato5`, `trace`, ou só `5`): ele roda inteiro e **volta à mesma pausa**. É para a pergunta fora de ordem.
| `◇ persona:` | para quem o passo fala. Use para escolher o que mostrar.
|===

[source,bash]
----
bash scripts/demo.sh --list      # todos os passos, a ordem, e as dependências
----
====
