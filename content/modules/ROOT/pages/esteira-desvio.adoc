:navtitle: {p-desvio}Desvio e reversão

**Para quem:** Engenheiro de Plataforma e quem responde por mudança em produção. · **12 min, parte deles esperando**

[NOTE.antes]
====
**Antes:** a parte xref:esteira-mr.adoc[{p-mr}Mudança por merge request]. Esta desfaz a mudança que você
fez lá (a xref:esteira-confere.adoc[{p-confere}] pode vir antes ou depois).
====

Duas perguntas de produção: **e se alguém mexer direto no cluster?** e **como
eu volto atrás?**

== Passo 1 -- mexa direto no cluster

É madrugada, um parceiro reclama, e alguém "só ajusta" o limite à mão: 9 no
lugar de 6.

[source,bash,role="execute perfil-dev",subs="attributes+"]
----
oc patch planpolicy travels-plans -n travel-agency --type=json -p '[{"op":"replace","path":"/spec/plans/2/limits/custom/0/limit","value":9}]'
sleep 11
for i in $(seq 14); do curl -s -o /dev/null -w '%{http_code} ' "https://{api_host}/travels?APIKEY={api_key_free}"; done; echo
bash scripts/esteira.sh estado
----

[source,text]
----
planpolicy.extensions.kuadrant.io/travels-plans patched
200 200 200 200 200 200 200 200 200 429 429 429 429 429
    repositorio            https://.../workshop/participantes/.../ambiente.git
    pasta                  esteira  (branch main)
    ultimo commit no Git   bbcc416b
    commit aplicado        bbcc416b
    cluster x Git          OutOfSync
      PlanPolicy/travels-plans  OutOfSync
----

**O que isso diz:** nove passam -- a mudança à mão **vale**. E a esteira a
acusa: `OutOfSync`, com o nome do objeto que desviou. Medido aqui: o desvio
aparece em cerca de um segundo.

[IMPORTANT]
====
**A esteira acusa o desvio e não o desfaz.** Neste workshop a correção
automática está desligada de propósito, para a diferença ficar visível. Com ela
ligada, a edição à mão seria desfeita em segundos -- e é assim que muito
ambiente de produção roda. As duas escolhas são legítimas; o que não é
aceitável é o desvio **não aparecer**.
====

== Passo 2 -- volte atrás, pelo Git

O pedido comercial foi cancelado: o plano free volta a 3. Você não precisa
lembrar o valor antigo, nem saber o que foi editado à mão: **desfaz o merge**
da parte xref:esteira-mr.adoc[{p-mr}] -- o comando o acha pelo nome do branch.

[source,bash,role="execute perfil-dev"]
----
git checkout -q main && git pull -q
git checkout -q -B volta-o-plano
git revert --no-edit -m 1 "$(git log --merges -1 --format=%H --grep=plano-free-6)" | head -1
git push -f -o merge_request.create -o merge_request.title='volta o plano free' origin volta-o-plano 2>&1 | grep -E 'merge_requests|new branch'
----

[source,text]
----
[volta-o-plano ...] Revert "Merge branch 'plano-free-6' into 'main'"
remote:   https://.../workshop/participantes/.../ambiente/-/merge_requests/2
 * [new branch]      volta-o-plano -> volta-o-plano
----

[IMPORTANT]
.Perfil Infra -- no GitLab, como `{usuario_console}`
====
Quem aceita é o **perfil Infra**. No navegador você já está no GitLab como
`{usuario_console}` (o login do console), que é *Maintainer* do projeto. Abra
o endereço do merge request: na aba **Changes** está a linha voltando a `limit: 3`; espere a conferência
**Pipelines as Code CI / confere** ficar verde e clique em **Merge**.
====


== Passo 3 -- espere a esteira, e meça

[source,bash,role="execute perfil-dev",subs="attributes+"]
----
git checkout -q main && git pull -q
bash scripts/esteira.sh espera
bash scripts/esteira.sh estado
sleep 11
for i in $(seq 14); do curl -s -o /dev/null -w '%{http_code} ' "https://{api_host}/travels?APIKEY={api_key_free}"; done; echo
----

[source,text]
----
    esperando o commit 5e01c3a7 chegar ao cluster ........................
    aplicado em 157s  (cluster x Git: Synced)
    repositorio            https://.../workshop/participantes/.../ambiente.git
    pasta                  esteira  (branch main)
    ultimo commit no Git   5e01c3a7
    commit aplicado        5e01c3a7
    cluster x Git          Synced
      PlanPolicy/travels-plans  Synced
200 200 200 429 429 429 429 429 429 429 429 429 429 429
----

**O que isso diz:** três passam, e o estado voltou a `Synced`. O revert levou
embora as **duas** coisas: a mudança do merge request e a edição à mão. Quando
a esteira aplica, vale o que está no Git.

== E quando o commit está errado?

Um commit que tenta sair do seu espaço é recusado **duas vezes**: antes do
merge, pela conferência da parte xref:esteira-confere.adoc[{p-confere}A esteira confere antes], e, se
passasse por ela, na hora de aplicar -- pelo projeto do Argo CD e pelas regras
de admissão do cluster (ver xref:fase-esteira.adoc[a cerca da esteira]). A
recusa da hora de aplicar aparece no mesmo lugar em que você leu `aplicado`:

[source,text]
----
    RECUSADO depois de 20s:
      one or more synchronization tasks are not valid: resource :ConfigMap is
      not permitted in project turma-...
----

== O que isso prova

**O Git manda, e voltar atrás é um commit.** O desvio aparece em vez de se
esconder, e desfazer uma mudança não depende de alguém lembrar como era.
