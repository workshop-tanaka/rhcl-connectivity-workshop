[NOTE.antes]
====
**Antes:** a parte xref:m1-02-planos.adoc[{p-planos}], que dá os três planos às
chaves. A xref:m3-03-negado.adoc[{p-negado}] ajuda a ler as recusas: as
estações que esta página cita são as dela.
====

O terminal prova o ponto com menos cliques, mas a maioria das pessoas testa API
no Postman -- e ver os cabeçalhos numa interface ajuda a fixar o que os
{m1e3} mostraram.

A coleção é a **bateria da borda** da parte {p-bateria}: o contrato do corpo,
as chamadas recusadas, os planos por dados e as versões, mais a autenticação
por identidade. O que roda no pod da {p-bateria}é o que você vai abrir aqui,
requisição por requisição, com as asserções visíveis na aba *Tests*.

== São três arquivos, e eles são diferentes

[cols="1,2",options="header"]
|===
| arquivo | o que é

| **a coleção** (`rhcl-demo.postman_collection.json`)
| as requisições. Não tem segredo nem endereço fixo dentro -- serve em
  qualquer cluster

| **o _environment_** (`rhcl-demo.local.postman_environment.json`)
| os endereços e as **chaves reais deste cluster**. É gerado na hora, nunca
  vem pronto

| **os dados por plano** (`rhcl-demo-planos.local.csv`)
| uma linha por plano: nome, chave e o limite que o repositório promete. É o
  que a pasta *Planos -- por dados* lê, uma rodada por linha; gerado junto
  com o _environment_
|===

O motivo da separação é o mesmo do workshop inteiro: o cluster é efêmero, e
valor copiado em arquivo envelhece.

== 1. Copie a coleção

Ela está no terminal do workshop. Mostre o conteúdo -- é longo, e o terminal
leva alguns segundos para despejá-lo:

[source,bash,role="execute"]
----
cat postman/rhcl-demo.postman_collection.json
----

Selecione tudo, copie, e salve na sua máquina como
`rhcl-demo.postman_collection.json`. A importação é no passo 3, junto com o
_environment_.

== 2. Gere o _environment_

No terminal do workshop:

[source,bash,role="execute"]
----
bash scripts/postman-env.sh
----

Ele descobre os endereços e as chaves **deste** cluster e escreve os dois
arquivos. Agora mostre o _environment_ para copiar:

[source,bash,role="execute"]
----
cat postman/rhcl-demo.local.postman_environment.json
----

São cerca de 20 linhas. Selecione, copie, e salve na sua máquina como
`rhcl-demo.postman_environment.json`. Faça o mesmo com
`postman/rhcl-demo-planos.local.csv` (quatro linhas), se for rodar a pasta
*Planos -- por dados* pelo *Collection Runner*, que pede o arquivo de dados.

[WARNING]
====
Esse arquivo contém **chaves de acesso reais**. Ele não vai para repositório
nenhum -- é ignorado pelo controle de versão de propósito -- e não deve ser
compartilhado.
====

== 3. Importe os dois no Postman

No Postman: botão **Import**, e arraste os dois arquivos (ou use *Select
files*). A coleção aparece na barra lateral; o _environment_ precisa ser
**selecionado no canto superior direito** para que as requisições encontrem
os endereços e as chaves.

[NOTE]
====
**Deixe a verificação de certificado ligada.** O certificado da API é emitido
por uma autoridade pública, e o Postman o aceita como aceitaria o de qualquer
site. Para conferir antes de importar:

[source,bash,role="execute perfil-qualquer",subs="attributes+"]
----
curl -s -o /dev/null -w 'verificacao: %{ssl_verify_result} (0 = confiavel)\n' https://{api_host}/travels
----

Se a verificação falhar num ambiente seu, o motivo é o certificado daquele
ambiente, não a API -- e desligar a verificação no Postman esconde o problema
em vez de resolvê-lo. A parte xref:m1-08-certificado.adoc[{p-certificado}] mostra de onde
vem esse certificado e quem o renova.
====

== O que tentar primeiro

Abra a pasta **A borda é fechada** e rode *sem chave -> 401*. Olhe a aba
**Headers** da resposta: lá está o `x-ext-auth-reason` da estação 3 da parte
{p-negado}, na interface em vez do terminal. Na aba **Test Results**, a
asserção com nome, verde.

Depois, na pasta **Contrato -- travels**, rode *GET /travels/Rome*: a aba
*Tests* mostra o JSON Schema que o corpo precisa cumprir. E, no *Collection
Runner* com o arquivo de dados, a pasta **Planos -- por dados** faz o `429`
mudo da estação 4, uma vez por plano -- você pode conferir na aba **Headers**
que não há nenhum cabeçalho explicando o limite.

== O que isso prova

A mesma API que o terminal exercita cabe numa ferramenta que o consumidor já
usa -- sem adaptação, sem proxy e sem instrução especial. O que ele precisa é
do endereço, da chave e do contrato.

É o teste mais próximo do que um cliente vai fazer no primeiro dia.
