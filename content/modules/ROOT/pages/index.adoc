= Connectivity Link -- a API como plataforma
:page-authorship: Sandro Tanaka

[.subtitulo]
_Workshop idealizado e construído por Sandro Tanaka._


A mesma API de viagens servida em três planos comerciais (`free`, `silver`,
`gold`), com o efeito visível na tela e mensurável no Grafana. A tese que cada
ato defende: **o Red Hat Connectivity Link é uma plataforma de API, não um
gateway** -- e nenhuma linha da aplicação muda para provar isso.

== O que você vai fazer

* Ver a API recusar quem não tem credencial, sem código de autenticação na aplicação (ato 1)
* Servir três clientes com três cotas a partir de **um label** num Secret (ato 2)
* Ler no status do cluster qual policy venceu, sem arqueologia (ato 3)
* **Entrar como o desenvolvedor** e sentir onde o apiserver recusa -- os dois papéis do Gateway API (ato 3b)
* Transformar `429` em "o tier free está saturando", no Grafana (ato 4)
* Seguir uma requisição do gateway até o banco, no grafo e no trace (ato 5)
* **Publicar uma API do zero** e levá-la de aberta a governada, uma policy por vez -- vendo a sobreposição acontecer na sua própria rota (ato 6)
* Provar que a chave de API abre a porta da rua, não o cofre: mTLS e identidade de serviço (ato 7)
* Alcançar um banco que **não está no cluster**, sem VPN e sem abrir porta nenhuma (ato 8)

Os extras (4b, 5b, 7b, 7c) respondem às perguntas que sempre aparecem: e se o
componente cair? quanto custa em latência? como é uma promoção de versão ao
vivo? e o que o Service Mesh **não** demonstra com fault injection.

== Para quem

Cada ato abre dizendo **a quem o problema pertence** -- Segurança, Engenheiro
de Plataforma, Produto, Operação/SRE, Desenvolvedor. Use isso para escolher
por onde começar: se você opera a plataforma, os atos 3, 4b e 7c falam
diretamente com o seu dia; se você desenvolve, o caminho 1 → 2 → 5 → 5b
responde primeiro o que costuma incomodar mais.

== A ordem importa

Os atos rodam soltos. O risco não é a ordem: é um ato que **lê** o que outro
**produziu** sair com painel vazio e sem erro. Cada página abre com um bloco
*Antes* dizendo o que pressupõe -- e o `demo.sh` confere e **pergunta** se
roda o pré-ato quando falta.

[cols="1,3,2",options="header"]
|===
| Ato | Precisa | Persona
| 1 | nada | Segurança · Plataforma
| 2 | cota do dia; 11 s desde a última rajada | Produto · Plataforma
| 3 | nada | Plataforma
| 3b | nada -- mas só faz sentido depois do 3 | Plataforma · Dev
| **4** | **ato 2 nos últimos 15 min** | Negócio · Operação
| 4b | Limitador de pé | Operação/SRE
| 5 | nada -- gera o próprio fan-out | Operação · Dev
| **5b** | **ato 5 na última hora** | Operação · Dev
| 6 | atos 1, 3 e 3b -- publica uma API do zero | Desenvolvedor · Plataforma
| **7** | **mesh no estado base** (STRICT, 90/10, sem fault) | Segurança · Plataforma
| 7b | discounts em 90/10 | Dev · Plataforma
| 7c | DestinationRule base | Operação/SRE
| 8 | a rede de serviços provisionada | Arquitetura · Operação
|===
