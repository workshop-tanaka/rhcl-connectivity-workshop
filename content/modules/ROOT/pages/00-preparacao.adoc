= 0. Preparação
:navtitle: 0. Preparação

Três minutos, uma vez. O terminal ao lado já está autenticado no cluster e já
tem tudo o que os atos executam.

== 1. Onde você vai trabalhar

[source,bash,role="execute"]
----
cd /home/lab-user/rhcl-connectivity-demo && ls scripts/
----

Tudo daqui em diante roda **de dentro desse diretório**. Os scripts descobrem
hostname, chaves e rotas do cluster na hora -- não há nada para configurar e
nada para baixar.

NOTE: O caminho é absoluto de propósito: neste terminal `~` aponta para
`/data`, que não é gravável; `/home/lab-user` é o volume persistente.

=== Onde a configuração vive

Tudo o que os atos citam está publicado no GitLab **deste cluster**, e cada
página linka o arquivo exato. Vale saber o mapa:

[cols="2,3",options="header"]
|===
| Projeto | O que tem

| {repo_policies}[rhcl/policies/rhcl-policies^]
| a camada de policies -- AuthPolicy, PlanPolicy, TelemetryPolicy, e o
  `base/mesh/` com VirtualService, DestinationRule, PeerAuthentication e
  AuthorizationPolicy. É o que os atos 1 a 4, 7 e 7b abrem.

| {repo_no_ambiente}[rhcl/base/rhcl-connectivity-demo^]
| a documentação, os templates do portal e os workloads da aplicação

| `rhcl/travel/*`
| um projeto por serviço (travels, flights, hotels, cars, insurances,
  discounts) -- é o que o Argo CD aplica
|===

{ide_url}[Abrir as policies no Dev Spaces^] sobe um IDE no próprio cluster com
esse repositório. Nada aqui depende de repositório fora do ambiente.

[NOTE]
====
Duas coisas que você **não** vai encontrar como arquivo, e é de propósito:

* **o `Gateway prod-web`** é *gerado* no provisionamento, porque o hostname
  depende do cluster -- fixá-lo num manifesto quebraria o próximo ambiente.
  Veja o objeto real com `oc get gateway prod-web -n ingress-gateway -o yaml`.
* **o que está em `platform-reference/`** (Istio, Tempo, Grafana, o disjuntor
  do ato 7c) é a plataforma que a demo *pressupõe*, não o que ela governa.
  Está no terminal, em `/home/lab-user/rhcl-connectivity-demo`.
====

== 2. O veredito

[source,bash,role="execute"]
----
bash scripts/demo.sh check --auto
----

Percorre a cadeia inteira na ordem do roteiro (~45 s) e termina em
`[OK] demo pronta.`. Um `✗` vermelho é bloqueante e vem com a correção ao
lado; avisos amarelos degradam um ato, não impedem o workshop.

== 3. As telas

[source,bash,role="execute"]
----
bash scripts/demo.sh telas --auto
----

Imprime a URL de cada aba que o roteiro abre, resolvida deste cluster. Deixe
abertas **em abas do navegador** -- o console, o Grafana e o Kiali mandam
`X-Frame-Options: DENY` e por isso não podem ser embutidos no painel à
direita; todos os links deste guia já abrem em aba nova. No painel ficam o
**Terminal** e o **Traces**, que é a única tela que aceita ser embutida.

[cols="1,3"]
|===
| Grafana | {grafana_url}/d/rhcl-evidencia[Evidência dos atos^] -- um painel por ato
| Kiali | {kiali_url}[Traffic Graph^] -- o grafo de tráfego (atos 5 e 7)
| Console | {openshift_console_url}/kuadrant/policy-topology[Policy Topology^] -- o fork do ato 3
|===

== 4. Como o `demo.sh` funciona

Cada passo **pausa antes de executar**: `Enter` segue, `p` pula, `Ctrl-C` sai.
Ele mostra o comando na tela antes de rodar, roda, e diz o que olhar na saída.

Três coisas que valem saber antes do ato 1:

[cols="1,3"]
|===
| `◇ depende:` | a linha abaixo do título diz o que o ato pressupõe. Quando falta, o script **pergunta** se roda o pré-ato agora e volta.
| Desvio | na pausa, digite o nome de outro ato (`ato5`, `trace`, ou só `5`): ele roda inteiro e **volta à mesma pausa**. É para a pergunta fora de ordem.
| `◇ persona:` | para quem o ato fala. Use para escolher o que mostrar.
|===

[source,bash]
----
bash scripts/demo.sh --list      # todos os passos, a ordem, e as dependências
----

== 5. (Opcional) Aquecimento

[source,bash,role="execute"]
----
bash scripts/demo.sh aquece --auto
----

Três minutos de tráfego de fundo e **depois** o reset das cotas. Sem ele o
Grafana do ato 4 mostra linha achatada. A ordem soak → reset é obrigatória:
o aquecimento queima cota diária, e o reset a devolve.

Pronto. Siga para o xref:01-ato1.adoc[ato 1].
