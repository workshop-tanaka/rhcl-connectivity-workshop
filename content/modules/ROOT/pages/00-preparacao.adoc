=== Dois terminais, dois perfis

Você trabalha com **duas identidades**, como numa empresa em que a borda e a
aplicação têm donos diferentes. Cada uma tem a sua aba, e as duas abrem no
mesmo diretório:

[cols="1,2,3",options="header"]
|===
| aba | perfil | o que pode

| `Terminal Infra`
| **Infra** -- Engenheiro de Plataforma
| o Gateway e as policies dele (o teto), certificados, DNS, os projetos de
  laboratório, as chaves de API e a leitura da plataforma -- e também a
  aplicação

| `Terminal Dev`
| **Dev** -- desenvolvedor da aplicação
| as rotas e as policies **da aplicação** (`HTTPRoute`, `AuthPolicy` e
  `PlanPolicy` dela) e a esteira; **lê** o Gateway e não o muda; não lê chave
  de API
|===

Todo bloco clicável diz de quem é, no título logo acima dele:

[source,text]
----
Perfil Infra -- aba Terminal Infra
Perfil Dev -- aba Terminal Dev
Consumidor da API -- qualquer aba
----

**Abra a aba indicada antes de clicar.** O botão do bloco manda o comando
para a aba que estiver aberta, seja qual for. Por isso todo bloco começa com
uma linha que diz de quem ele é -- `perfil infra && {` ou `perfil dev && {`
--, e o resto vem entre chaves: o terminal confere a aba antes de rodar
qualquer linha do bloco.

* **na aba certa**, ela responde `perfil Dev -- aba Terminal Dev` (ou Infra) e
  o bloco segue;
* **na aba errada**, nada roda: o terminal avisa em qual aba você está e
  pergunta `Executar mesmo assim como Infra? [s/N]`. `Enter` responde não.
  Responda `s` só se quiser ver, de propósito, o que a outra identidade
  consegue fazer -- o resultado pode não ser o que a página mostra.

O terceiro título é o de quem **consome** a API: o bloco é só uma chamada
HTTP com a chave de um plano, sem identidade nenhuma do cluster. Ele roda em
qualquer aba e não pergunta nada -- do lado de fora, nenhum dos dois perfis
existe.

Experimente com os dois blocos abaixo. Clique no primeiro com a aba `Terminal
Infra` aberta; troque para a `Terminal Dev` e clique no segundo:

[source,bash,role="execute"]
----
oc whoami
----

[source,bash,role="execute perfil-dev"]
----
oc whoami
----

Na aba `Terminal Infra`, `system:serviceaccount:showroom-...:showroom` é o
Infra. Na `Terminal Dev`, `system:serviceaccount:travel-agency-...:dev` é o
Dev. Agora clique no segundo bloco com a aba `Terminal Infra` aberta: é a
pergunta acima que aparece.

Quando uma página pede ao perfil errado uma ação que não é dele, de
propósito, o erro vem anunciado assim:

[WARNING]
.Erro esperado -- o perfil Dev não tem essa permissão
====
A recusa é o resultado. Leia a mensagem: ela diz **quem** tentou e **o que**
foi negado.
====
endif::[]

NOTE: O caminho é absoluto de propósito: neste terminal `~` aponta para
`/data`, que não é gravável; `/home/lab-user` é o volume persistente.

=== Onde a configuração vive

A configuração que as partes citam está **no cluster**, e cada página traz o
comando que a mostra -- por exemplo:

[source,bash,role="execute"]
----
oc get planpolicy travels-plans -n travel-agency -o yaml
----

O que você lê assim é o objeto em vigor, com o status que a plataforma
escreveu nele. Os mesmos objetos existem como arquivo no terminal, para quem
quiser ver como foram declarados:

[source,bash,role="execute"]
----
ls base/
----

[cols="2,3",options="header"]
|===
| Diretório | O que tem

| `base/policies-*`
| a camada de policies -- AuthPolicy, PlanPolicy e TelemetryPolicy

| `base/mesh/`
| VirtualService, DestinationRule, PeerAuthentication e AuthorizationPolicy
|===

[NOTE]
====
Duas coisas que você **não** vai encontrar como arquivo, e é de propósito:

* **o `Gateway prod-web`** é *gerado* no provisionamento, porque o hostname
  depende do cluster -- fixá-lo num manifesto quebraria o próximo ambiente.
  Veja o objeto real com `oc get gateway prod-web -n ingress-gateway -o yaml`.
* **o que está em `platform-reference/`** (Istio, Tempo, Grafana, o circuit breaker
  da parte {p-resiliencia}) é a plataforma que a demo *pressupõe*, não o que ela governa.
  Está no terminal, em `/home/lab-user/rhcl-connectivity-demo`.
====

== 2. O veredito

Antes da primeira parte, confirme que o ambiente nasceu inteiro. Um ambiente
incompleto não dá erro logo: ele falha no meio de uma parte, com painel vazio
ou número que não bate.

[source,bash,role="execute"]
----
bash scripts/demo.sh check --auto
----

Percorre a cadeia inteira -- operadores, gateway, policies, chaves, caminho de
dados, Service Mesh, portais e portal do desenvolvedor. Leva
**cerca de dois minutos** e termina assim:

[source,text]
----
  ✓ sem chave -> 401 (a borda fechada)
  ✓ cota diaria: gold 99980/100000, free 989/1000, silver 9987/10000
  ✓ tier free: 3 servidas, 5 limitadas (planos comerciais)
  ...
[OK] o ambiente esta inteiro
----

Como ler o resultado:

[cols="1,3",options="header"]
|===
| o que aparece | o que fazer

| `[OK]` no fim
| siga para a parte {p-fechada}

| `!` amarelo
| **não bloqueia.** Degrada uma parte específica, e a linha diz qual

| `✗` vermelho
| bloqueia. Cada `✗` vem com a correção ao lado -- rode o que ele indica e
  repita a checagem

| o comando não responde
| a sessão do terminal caiu; abra a aba do terminal de novo e repita
|===

.Uma checagem mais curta, para o meio do workshop
[%collapsible]
====
A checagem completa confere coisas que só interessam a alguns módulos. Se você
só quer saber se o **caminho de dados** está de pé -- a API, as policies e os
planos --, há uma versão de cerca de 50 segundos:

[source,bash,role="execute"]
----
bash scripts/preflight.sh core
----

Ela termina em `[OK] núcleo pronto`. É a que vale rodar se uma parte devolver
um número estranho no meio do caminho.
====

== 4. Como o `demo.sh` funciona

Cada passo **pausa antes de executar**: `Enter` segue, `p` pula, `Ctrl-C` sai.
Ele mostra o comando na tela antes de rodar, roda, e diz o que olhar na saída.

Três coisas que valem saber antes da parte {p-fechada}:

[cols="1,3"]
|===
| `◇ depende:` | a linha abaixo do título diz o que a parte pressupõe. Quando falta, o script **pergunta** se roda a parte anterior agora e volta.
| Desvio | na pausa, digite o nome de outro passo do roteiro (`ato5`, `trace`, ou só `5`): ele roda inteiro e **volta à mesma pausa**. É para a pergunta fora de ordem.
| `◇ persona:` | para quem a parte fala. Use para escolher o que mostrar.
|===

[source,bash]
----
bash scripts/demo.sh --list      # todos os passos, a ordem, e as dependências
----
