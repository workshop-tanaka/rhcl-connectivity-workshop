= {p-mr}Mudança por merge request
:navtitle: {p-mr}Mudança por merge request

**Para quem:** Desenvolvedor e Engenheiro de Plataforma -- quem muda um limite e quem aprova. · **15 min, parte deles esperando**

[NOTE.antes]
====
**Antes:** a parte xref:esteira-fonte.adoc[{p-fonte}O repositório é a fonte], que mostra o que a esteira
aplica.
====

O pedido é comercial: **o plano free passa de 3 para 6 chamadas a cada 10
segundos.** Você vai atendê-lo sem rodar `oc apply`.

ifdef::perfis[]
Esta fase é do **perfil Dev**: os comandos rodam na aba `Terminal Dev`.
endif::[]

== Passo 1 -- como está hoje

Uma rajada de 14 chamadas com uma chave do plano free.

[source,bash,role="execute perfil-qualquer",subs="attributes+"]
----
for i in $(seq 14); do curl -s -o /dev/null -w '%{http_code} ' "https://{api_host}/travels?APIKEY={api_key_free}"; done; echo
----

[source,text]
----
200 200 200 429 429 429 429 429 429 429 429 429 429 429
----

**O que isso diz:** três passam, o resto é cortado. É o limite que está no Git.

== Passo 2 -- a mudança, num branch

O comando cria um branch, troca o número no arquivo da pasta `esteira/` e
grava a mudança com uma mensagem que diz o porquê. Se você já fez esta parte
antes, o `-B` recria o branch a partir do `main` de agora.

[source,bash,role="execute perfil-dev"]
----
git checkout -q main && git pull -q
git checkout -q -B plano-free-6
sed -i '/tier: free/,/window/ s/limit: 3/limit: 6/' esteira/planos.yaml
git diff -U0 | grep '^[-+] '
git commit -q -am 'plano free: de 3 para 6 chamadas a cada 10s' && git log --oneline -1
----

[source,text]
----
-          - limit: 3
+          - limit: 6
... plano free: de 3 para 6 chamadas a cada 10s
----

**O que isso diz:** a mudança inteira é uma linha. Ela ainda está só no seu
terminal: nada mudou no repositório nem no cluster.

== Passo 3 -- tente o atalho

Empurre a mudança direto para o `main`, sem pedir a ninguém.

[source,bash,role="execute perfil-dev"]
----
git push origin plano-free-6:main 2>&1 | grep -E 'remote: GitLab|rejected'
----

[source,text]
----
remote: GitLab: You are not allowed to push code to protected branches on this project.
 ! [remote rejected] plano-free-6 -> main (pre-receive hook declined)
----

[WARNING]
.Erro esperado -- o perfil Dev não escreve direto no `main`
====
A recusa é o resultado. O `main` é o que a esteira aplica, e ninguém escreve
nele direto: o repositório recusa (`not allowed to push code to protected
branches`). Não é um combinado de equipe. O único caminho até o cluster passa
por um merge request.
====

== Passo 4 -- abra o merge request

[source,bash,role="execute perfil-dev"]
----
git push -f -o merge_request.create -o merge_request.title='plano free: de 3 para 6' origin plano-free-6 2>&1 | grep -E 'merge_requests|new branch'
----

[source,text]
----
remote:   https://.../workshop/participantes/.../ambiente/-/merge_requests/1
 * [new branch]      plano-free-6 -> plano-free-6
----

.Se o merge request aparecer como *Draft*, ou a saída não trouxer o endereço
[%collapsible]
====
O GitLab abre como rascunho (*Draft:* no título) o merge request cujo branch
não traz **nenhum commit** além do `main` -- medido neste ambiente: os quatro
merge requests vazios de uma rodada saíram *Draft*, e nenhum dos que tinham
commit. Acontece quando o commit do passo 2 não foi para o branch. Confira:

[source,bash,role="execute perfil-dev"]
----
git log --oneline origin/main..plano-free-6
----

Sem nenhuma linha, rode o passo 2 de novo e depois este passo: o `-f` do push
substitui o branch antigo, e o mesmo merge request passa a mostrar a mudança.
====

O merge request foi aberto por `{usuario_console_dev}`: o terminal Dev empurra
com a identidade Dev, que no projeto é *Developer*. E o `main` só aceita merge
de *Maintainer*.

[WARNING]
.Recusa esperada -- o Dev não aceita o próprio merge request
====
Quem propõe não aprova. Entrando no GitLab como `{usuario_console_dev}`, o
merge request aparece com a conferência, mas **sem o botão Merge**; e um
pedido de merge automático feito pelo Dev é ignorado, sem erro -- o merge
request fica aberto esperando quem pode aceitá-lo. Não é um combinado: é a
regra do branch.
====

[IMPORTANT]
.Perfil Infra -- no GitLab, como `{usuario_console}`
====
Quem aceita é o **perfil Infra**. No navegador você já está no GitLab como
`{usuario_console}` (o login do console), que é *Maintainer* do projeto. Abra
o endereço do merge request: na aba **Changes** está a linha que mudou -- é isso que quem aprova lê; espere a conferência
**Pipelines as Code CI / confere** ficar verde e clique em **Merge**.
====

**O que isso diz:** a mudança agora tem autor, texto, data, uma conferência
automática e **outra pessoa** que a aceitou. É a separação de funções que
qualquer auditoria pede: o Dev propõe, a máquina confere, o Infra aprova, o
Argo CD aplica.

== Passo 5 -- espere a esteira, e meça

O primeiro comando espera o commit do merge chegar ao cluster e diz quanto
levou. Depois, a mesma rajada do passo 1.

[source,bash,role="execute perfil-dev",subs="attributes+"]
----
git checkout -q main && git pull -q
bash scripts/esteira.sh espera
sleep 11
for i in $(seq 14); do curl -s -o /dev/null -w '%{http_code} ' "https://{api_host}/travels?APIKEY={api_key_free}"; done; echo
----

[source,text]
----
    esperando o commit bbcc416b chegar ao cluster .............................
    aplicado em 281s  (cluster x Git: Synced)
200 200 200 200 200 200 429 429 429 429 429 429 429 429
----

**O que isso diz:** seis passam. Ninguém rodou `oc apply`: o limite mudou
porque um merge request foi aceito.

[IMPORTANT]
====
**A espera varia.** O GitLab avisa o Argo CD a cada push, e a mudança costuma
chegar em segundos; medi de 1 segundo a quase 4 minutos neste ambiente. Sem
esse aviso, o Argo CD só consulta o repositório de tempos em tempos -- medido:
157 a 354 segundos. O comando espera em vez de prometer um tempo.
====

== O que isso prova

**A mudança tem dono, revisão e data -- e a entrada por fora aparece.** O limite de um plano deixou de ser um comando que alguém rodou e
virou uma linha num histórico.
