== As três chaves

Cada uma representa um cliente num plano comercial diferente. É a diferença
entre elas que a parte {p-planos} explora:

[cols="1,1,2",options="header"]
|===
| plano | para que serve | chave

| gratuito
| o limite mais apertado, e o que estoura primeiro
| `{api_key_free}`

| intermediário
| o meio-termo
| `{api_key_silver}`

| completo
| o que passa quando os outros já foram recusados
| `{api_key_gold}`
|===

Para chamar a API com uma delas, a chave vai no header `Authorization`:

[source,bash,role="execute perfil-qualquer",subs="attributes+"]
----
curl -sk -H 'Authorization: APIKEY {api_key_gold}' "https://{api_host}/travels" | head -c 300
----

[NOTE]
====
A chave vai no header `Authorization: APIKEY <chave>`, e não na URL: assim ela
fica fora do log de acesso e do endereço de cada trace. A parte {p-fechada}
mostra a policy que a lê de lá.
====

=== O seu repositório e o roteiro

Os dois ficam no GitLab deste ambiente. Na tela de login, clique em **Entrar
com o usuario do console** e use o mesmo usuário e a mesma senha do Console do
OpenShift -- não há conta separada.

* **O seu repositório** é a cópia que está no terminal do guia, em
  `/home/lab-user/rhcl-connectivity-demo`: policies, overlays e os scripts que
  as partes mandam rodar, com os namespaces e hostnames do seu ambiente. Pode
  editar e criar branch à vontade; nada dali é aplicado ao cluster sozinho.
* **O roteiro** traz os mesmos arquivos com os nomes genéricos. Serve para
  comparar com os seus, e ninguém da turma escreve nele.

O diretório do terminal já é um clone do seu repositório. `git status`,
`git commit` e `git push` funcionam dali, sem digitar credencial:

[source,bash,role="execute"]
----
git status -sb
----
endif::[]
