== O que você percorreu

Quatro módulos, três produtos, e **uma aplicação que não mudou uma linha**. O
binário do `travels` é o mesmo do primeiro ao último exercício.

[cols="1,2",options="header"]
|===
| fronteira | o que ficou provado

| **norte-sul** -- quem entra
| A API é fechada por padrão, distingue planos comerciais no mesmo endereço, e
  o consumo vira número. Nenhuma linha de aplicação trata disso.

| **leste-oeste** -- quem fala com quem
| Uma chave de API abre a porta da rua, não o cofre: dentro, quem autoriza é a
  identidade do serviço.

| **entre sites** -- o que não mora aqui
| O componente que "não vai para o Kubernetes" não precisa ir. Precisa ser
  alcançável.

| e sobre as três
| Observabilidade e diagnóstico: seguir uma requisição salto a salto, e dizer
  em qual de seis lugares uma recusa morreu.
|===

== A tese, agora que dá para conferir

Seis policies, um alvo. Autenticação, limite, plano, telemetria -- e, onde há
DNS público, certificado e DNS -- todas mirando o mesmo Gateway, todas com
status próprio, nenhuma escondida num campo de anotação.

E uma ressalva que o workshop fez questão de medir em vez de omitir:
**`Enforced=True` não é promessa de efeito.** A parte 1.9 mostra uma policy
aceita, programada, com status verde -- e sem efeito nenhum sobre o tráfego.
Quem confia no status sem medir o comportamento acredita num limite que não
existe.

Uma plataforma de API governa a borda inteira. E dizer isso com honestidade
inclui dizer onde ela ainda não chega.

== O que ficou para trás

[source,bash,role="execute"]
----
bash scripts/demo.sh pos --auto
----

Procura o que os exercícios deixaram para trás (mTLS em PERMISSIVE, fault
injection, canário fora de 90/10, cota baixa), ajusta, e revalida. Rode-o
quando quiser recomeçar do zero. Para repetir as partes no mesmo dia,
`bash scripts/demo.sh reset` devolve as cotas diárias.

== As quatro perguntas que este workshop existe para responder

[cols="1,2"]
|===
| JWT/OIDC em vez de API key? | Sim -- a AuthPolicy aceita os dois; a demo usa chave porque cabe numa tela.
| Cobrança por consumidor? | É por **plano**, e o motivo é técnico: o contador é por tier, e o label do parceiro é dimensão de métrica, não de limite.
| E se o Limitador cair? | `failureMode: allow` -- a parte 3.4 mede isso. A autenticação é o oposto.
| Quanto custa em latência? | Duas chamadas gRPC, visíveis no trace -- a parte 3.2 mede isso.
|===

== Para levar

O ambiente fica de pé até o fim da sua reserva: repita as partes quantas vezes
quiser. No terminal, `bash scripts/demo.sh --list` mostra todos os passos, o
que cada um pressupõe e para quem ele fala.

Tudo que o workshop usou -- documentação dos produtos, os projetos por trás, a
configuração versionada e a coleção do Postman -- está reunido em
