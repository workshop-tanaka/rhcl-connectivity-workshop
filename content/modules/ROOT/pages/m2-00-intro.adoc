= Módulo 2 — Service Mesh: a fronteira de dentro
:navtitle: Módulo 2 — Introdução

**Três partes · cerca de 16 minutos · todas mudam estado**

**Produto protagonista:** Red Hat OpenShift Service Mesh

== O que você vai conseguir fazer

* explicar por que proteger a entrada não protege o que acontece lá dentro;
* colocar uma versão nova no ar recebendo uma fração do tráfego;
* distinguir as duas respostas que uma plataforma dá quando o serviço do outro
  lado começa a falhar -- e por que as duas devolvem o mesmo código;
* distinguir os dois `503` que o Service Mesh produz quando o serviço do outro
  lado começa a falhar.

== A ideia que atravessa as quatro partes

Os módulos anteriores trataram a **borda**: quem entra, quanto passa, quanto
custa. Mas uma aplicação real é feita de serviços que se chamam entre si -- e
uma chave de API que abre a porta da rua não diz nada sobre quem pode abrir as
portas internas.

Este módulo é sobre essa segunda fronteira, a **leste-oeste**.

== O que você precisa antes

O Módulo 1. As partes 2.2 e 2.3 partem do estado que a 2.1 estabelece, então
vale fazê-las na ordem.

== Aviso

As três alteram configuração de tráfego e a revertem no fim. Se você
interromper uma delas no meio, o comando `bash scripts/demo.sh mesh_base`
devolve tudo ao estado inicial.
